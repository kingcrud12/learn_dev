## Comment aborder un projet

Un projet n'est pas un exercice. Un exercice a une solution ; un projet a des
**arbitrages**.

L'ordre de travail est toujours le même, et l'inverse de celui qu'on adopte
spontanément :

1. **Comprendre le problème** — le domaine, le vocabulaire, les contraintes.
   Avant toute technique.
2. **Décider l'architecture** — les frontières, et ce qui est remplaçable.
3. **Écrire le contrat** — entre les composants, avant de les écrire.
4. **Construire en tranches verticales** — une chaîne complète et étroite,
   qu'on épaissit ensuite.

Le réflexe naturel est de commencer par le code. Le résultat est un projet dont
la structure est un accident de ses premières heures.
